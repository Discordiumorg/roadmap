# Discord bot evaluation worksheet

Published by the Discordium team. Links to Discordium lead to our own resources.

Use this worksheet to compare bots against a real community task. Record evidence rather than giving a bot a trust score based on its popularity.

## Define one task

Write down what a member does, what a moderator should see, and the expected result. For example: a member opens a support request, receives an acknowledgement, and can find the response later.

Browse the [Discord bot directory](https://discordium.org/bots) to identify candidates, then verify details in each developer's own documentation.

## Test the actual workflow

- Try a normal action and an incomplete request.
- Try the action with a role that should not have access.
- Check member-facing messages and moderator visibility.
- Verify time zones and cancellation for scheduled events.
- Check how support requests close and how authorized staff find them later.
- Avoid using private member conversations or credentials as test data.

## Record a decision

Choose **meets the need**, **needs clarification**, or **does not fit**. Add a reason and the test date. Keep access concerns separate from convenience.

For your own listing, review the [Discordium listing guidelines](https://discordium.org/guidelines) and describe available features, setup and paid limits accurately.

## Make replacement possible

Keep a short configuration handover and a review trigger: changed permissions, pricing limits, missing features or a new support process. Assign an owner to unanswered questions.

Developers integrating with Discordium should consult the [Discordium Developer API documentation](https://discordium.org/developers). Keep integration credentials out of public worksheets.
